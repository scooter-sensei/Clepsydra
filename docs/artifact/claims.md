# Claims and how each is checked

Every claim made about this filter (the paper, the specification, the record of the work, and the project thread) is listed here with the command that checks it, the result, and a status:

- **checked**: deterministic; `verify/run.sh` re-computes it and requires a byte-for-byte match with `verify/expected/`.
- **replayed**: re-derived from the git history by `verify/replay.sh` (old commits, or today's harness on old library code).
- **derived**: follows from the code or from arithmetic shown here.
- **host**: a speed figure. It depends on the machine; [speed-runs.md](speed-runs.md) has the reference runs and `verify/ab.sh` repeats any comparison. Compare ratios, not absolute numbers.
- **sampled**: randomized by design (each arm draws its hash seeds per process), pooled over rounds with a 95% interval; re-run by its command, it must fall inside the stated interval.
- **corrected**: an earlier claim that the checks showed to be wrong; the corrected statement is given.
- **unverifiable**: no code or data was kept to re-check it. Treat as anecdote.

Run everything: `verify/isolated.sh` (fresh clone from a git bundle, official Go 1.24.7 image pinned by digest, `--network none`, empty caches), or `verify/run.sh` in any clean checkout. Deterministic results hold for linux/amd64 with Go 1.24.7 and with Go 1.27.3, the toolchain `go/go.mod` names (D23), and for linux/arm64 under qemu-user 10.2.1 (`./test.sh regression` byte for byte, at a6f7ea6; see [reproducing.md](reproducing.md#other-architectures)); no arm64 hardware was tested. The last runs (Docker and unshare, all checks pass) are recorded in [isolated-runs.md](isolated-runs.md).

Commands run in `go/`. "This host" in a speed claim is the host its section names ([hosts](../README.md#hosts)); the placement study's readings M1–M9 are defined in [measuring-speed.md](measuring-speed.md#the-readings). Item numbers ("changes 10", "changes item 16") refer to [record/changes.md](../record/changes.md).
