**Host**:
- Run WSL work through script files (`MSYS_NO_PATHCONV=1 wsl bash -lc 'bash "/mnt/.../x.sh"'`): inline `$VAR`s and `;` are split or expanded on the Windows side before bash sees them.
- **WSL shuts down when the launching `wsl` command returns**, killing `nohup`/`setsid` jobs: run queues from a background command that holds `wsl` open. To stop one, kill its process tree inside WSL (`stoptree.sh PID`); stopping the Windows-side command alone may leave it running while another `wsl` holds WSL open.
- Bash reads a running script as it goes: don't edit a queue that has started, even one waiting in a loop; stop it and launch a new one.
- `-race` needs `CGO_ENABLED=1 CC=$HOME/bin/zcc GOFLAGS=-ldflags=-linkmode=external`.
- Python isn't on the Windows side; use WSL's. Go isn't either.
- `pkill -f PATTERN` also kills the shell that runs it when its own command line matches: put it in a script whose path doesn't.
- A queue waiting on `pgrep -f "[q]N.sh"` matches any process whose command line names it: chain queues, or wait on a marker line in a summary file.
- arm64 under qemu: `GOARCH=arm64 GOFLAGS=-exec=qemu-aarch64 ./test.sh <tier>`; sanity takes ~8 min.
- In Go, `1<<tagBits-1<<36` is `(1<<tagBits) - (1<<36)`: parenthesize masks before shifting them.
