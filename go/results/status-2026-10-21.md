## Decisions

**Protocol**
- Every hold of an occupied slot (word1 busy: relocation, eviction, realign, the decay sweep, an insert over an expired entry) counts as a move of the occupant's stripe, so a lookup that misses the slot meanwhile looks again instead of inserting the key a second time (DESIGN; A26, A27; `SlotHold.tla`).
- A hot history whose entry was reclaimed is gone: the recalling touch starts it afresh (A25).

**Method (additions)**
- A race that doesn't reproduce on demand gets a trace build before a guess; when even that is too rare, an invariant detector (a key in two visible slots) turns rare failures into frequent signals. Its scan must be bracketed by the key's stripe move counts, or a relocation in flight reads as a duplicate (the first version's three hits were all that).
- A layout control in an A/B must be linked code (a function called once from `New`): an uncalled function is dropped by the linker and measures identical programs (X33). On this host a 32-byte placement change moves TouchAndCount's importer loop ~3% (S49).
- A guard the fuzzer can't reach (A26's second half, A27) is carried by hook tests and a model; say so in its claim. The straggler mode was tried for power over them and has none.
- A model that omits a lock the code takes can report a false bug: SlotHold's first version found a duplicate that the claim stripe prevents.

**Left to the user**: whether Background becomes the default; row 7's target.
