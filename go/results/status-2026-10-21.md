**Tests (committed):** A36 (the fuzzer's second direction); `TestTickRange`, `TestRegressTickPastRange`, `TestGhostReadAcrossEpoch`.

**Method (additions):**
- Read the code against each claim's premise, not only the claim: A34's decode and A35's tick range were each one assumption no test exercised.
- An oracle that checks one direction can't see the other's bugs: give each invariant its converse where one exists, and plant a bug to show the check has power.
- Measure speed over random layouts (`verify/lrab.sh`), and set bars a no-op can pass: here a pure shift reads up to 2% on HitHot and a 1.03 bound on the interval is out of reach at 10 layouts.
- Follow the rule written before the reading even when the data look clean: the dither stays an experiment and the guard moved, because their intervals missed the bars.
- A `go test` file the replay copies into old commits must use only the old API (`regress_test.go`).

**Prior art:** Mytkowicz et al., "Producing Wrong Data Without Doing Anything Obviously Wrong!" (ASPLOS 2009), and Curtsinger and Berger, "Stabilizer" (ASPLOS 2013): measurement bias from code layout, and randomized layout as its cure; `verify/lrab.sh` is a compile-time, three-point version.
